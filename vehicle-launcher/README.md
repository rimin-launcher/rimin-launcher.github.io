# Sealion One — 씨라이언7 통합 런처 + 휴대폰 키

차량용 홈 런처(**Sealion One**)와 휴대폰 앱(**Sealion One Key**)이 한 세트로 동작합니다.

| 모듈 | 설치 위치 | 역할 |
|---|---|---|
| `launcher/` | 차량 헤드유닛 (DiLink, Android 11) | 홈 화면 · 대시보드 · 공조/시트 · 차량 제어 · 주행 기록 · 앱 · 휴대폰 키 수신 |
| `phone/` | Android 휴대폰 (8.0+) | 접근 시 자동 열림 · 이탈 시 자동 잠금 · 원격 버튼 · 바로가기 |
| `core/` | 공용 (순수 Kotlin) | 페어링 · 서명된 BLE 명령 · 접근/이탈 판단 로직 (단위 테스트 포함) |

> reference launcher·reference app의 **공개된 기능 설명을 참고해 새로 작성한 코드**입니다. 두 앱의 코드·디자인·리소스는 사용하지 않았습니다.
> BYD의 공식 제품이 아닙니다.

## 화면 구성 (차량)

- **대시보드** – 속도계(아날로그/숫자), 기어, 배터리·주행 가능 거리, 오늘 주행 거리, 실내·실외 온도, 미디어 재생/컨트롤
- **공조 · 시트** – 운전석/동승석 온도(± 버튼 + 드래그 바), 공조·A/C·AUTO·내기 순환·앞유리 제상·뒷유리 열선, 풍량 1–7, **시트 열선 / 통풍 0–3단계**, 핸들 열선
- **차량 제어** – 잠금 · 열림 · 트렁크 · 창문 닫기 · 공조 켜기/끄기 · 차량 찾기 + 최근 동작 기록
- **주행 기록** – 주행별 거리·시간·평균/최고 속도, 월간 거리, 추정 전력·충전 비용·전비
- **앱** – 전체 앱, 검색, 길게 눌러 독에 추가
- **독(항상 표시)** – 내비 · 미디어 · **공조 바로가기 줄**(양쪽 온도 ±, 운전석 열선·통풍, 핸들 열선, 동승석 열선 — 누를 때마다 한 단계씩) · 즐겨찾는 앱 · 설정

모든 버튼은 운전 중 조작을 고려해 52–76dp 크기로 만들었습니다.

## 설정 메뉴

화면(강조 색상 6종, 밝은/어두운, 24시간제, 전체 화면, 속도계) · 독/앱 · 차량 자동화(주행 중 자동 잠금 속도, P단 자동 열림) ·
휴대폰 키(등록 QR, 키 재발급, 차량 이름) · 음성 안내(기어 변경, 과속 알림, 음량) · 주행 기록(충전 단가, 배터리 용량, 기록 삭제) ·
내비·미디어(앱 선택, 알림 접근) · 시스템(시작 시 무선 ADB, 데모 모드, **진단 · 차량 SDK**)

## 휴대폰 키 — 자동 잠금 · 열림

```
 휴대폰 (Sealion One Key)                    차량 헤드유닛 (Sealion One)
 ─────────────────────────                    ────────────────────────────
 BLE 스캔 → 신호 세기(RSSI)  ◀── 광고 ───────  BLE 광고 (차량별 태그)
 걸음 센서 → 최근 걸음 수
 ProximityEngine: 접근/이탈 판단
   └ 연결 → nonce 읽기       ◀─────────────── 1회용 nonce 발급
   └ HMAC 서명 명령 전송      ────────────────▶ 서명·재전송 검증 → 도어 잠금/열림
   └ 결과 수신               ◀─────────────── 결과 알림
```

- **등록**: 차량 설정 › 휴대폰 키 › 휴대폰 등록의 QR을 앱으로 스캔합니다. 32바이트 키는 휴대폰의 Android Keystore에 내보낼 수 없는 형태로 저장됩니다.
- **판단 기준**: 신호가 열림 기준(기본 −68 dBm)보다 강해지면 열림, 잠금 기준(기본 −86 dBm)보다 약해지거나 12초간 사라지면 잠금. 기본적으로 **걸어서 이동 중일 때만** 판단해 집 안에서 신호가 오락가락해도 동작하지 않습니다. 같은 동작은 45초 안에 반복되지 않습니다.
- **보안**: 명령마다 1회용 nonce + 증가 카운터 + HMAC-SHA256. 다른 키, 재전송, 15초 지난 요청, 변조된 명령은 거부됩니다(`core` 단위 테스트로 확인). 주행 중(3 km/h 초과)에는 열림·트렁크 명령을 거부합니다.
- **알림·바로가기**: 상시 알림에 잠금/열림/트렁크 버튼, 앱 아이콘 길게 누르기 바로가기(잠금·열림·트렁크·공조).

### 휴대폰 키 동작 범위 (중요)

헤드유닛이 **켜져 있을 때만** 명령을 받을 수 있습니다. 하차 직후 걸어가며 잠그는 것은 헤드유닛이 아직 켜져 있으므로 동작하지만,
차량이 완전히 잠든 뒤 다가가서 여는 것은 헤드유닛이 꺼져 있으면 동작하지 않습니다. 이 경우는 차량 기본 키/BYD 앱을 사용하세요.
(BYD 클라우드 연동은 비공개 프로토콜이라 포함하지 않았습니다.)

신호 세기 기반 자동 열림은 원리상 릴레이 공격에 취약할 수 있습니다. 불안하면 앱에서 ‘다가가면 자동 열림’을 끄고 자동 잠금만 쓰세요.

## 차량 SDK 연동과 검증

차량 데이터와 제어는 헤드유닛의 비공개 BYD SDK(`android.hardware.bydauto.*`)를 리플렉션으로 호출합니다(`launcher/.../vehicle/BydAutoVehicle.kt`).
메서드 이름은 공개된 커뮤니티 자료를 바탕으로 한 **후보**이며, 펌웨어마다 다를 수 있습니다.

1. 차량에 설치 후 **설정 › 시스템 › 진단 · 차량 SDK**를 엽니다.
2. 각 장치(속도·통계·기어·도어락·차체·공조·조명·시트·설정)의 실제 메서드와 상수 목록이 표시됩니다.
3. 값이 ‘—’이거나 버튼이 ‘차량 미지원’이면 그 목록을 보고 `BydAutoVehicle.kt`의 후보 이름을 맞추면 됩니다.

SDK가 없는 기기(에뮬레이터·태블릿)에서는 자동으로 **데모 차량**으로 동작하므로 화면과 휴대폰 키 연동을 미리 시험할 수 있습니다.

## 빌드

```bash
cd vehicle-launcher
./gradlew :core:test                      # 프로토콜·근접 판단 단위 테스트
./gradlew :launcher:assembleDebug :phone:assembleDebug
./gradlew :launcher:testDebugUnitTest -Pscreenshots   # 화면 렌더링 → launcher/build/screenshots/*.png
```

JDK 17+, Android SDK 34 필요. GitHub Actions(`.github/workflows/android.yml`)가 푸시마다 디버그 APK 두 개를 아티팩트로 만듭니다.
릴리스 서명은 `vehicle-launcher/keystore.properties`(storeFile, storePassword, keyAlias, keyPassword)를 두면 적용됩니다 — 이 파일과 키는 커밋하지 마세요.

## 설치

**차량** (PC 또는 무선 ADB 앱 사용)

```bash
adb connect <차량 IP>:5555
adb install -r launcher-release.apk
# 선택: 시작할 때마다 무선 ADB 켜기
adb shell pm grant kr.personal.sealion.one android.permission.WRITE_SECURE_SETTINGS
```

설치 후 설정 › 독·앱 › 기본 홈 앱 설정에서 Sealion One을 선택하고, 미디어 정보를 보려면 알림 접근을 허용합니다.
기본 홈 변경과 BYDAUTO 권한 부여는 차량 펌웨어가 허용해야 합니다.

**휴대폰**: `phone-release.apk` 설치 → 권한 허용(블루투스·근처 기기·신체 활동·알림) → 배터리 최적화 제외 → QR 스캔.
